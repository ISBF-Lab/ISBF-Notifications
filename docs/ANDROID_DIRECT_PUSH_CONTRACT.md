# Android 直连通知：统一事件开关接入

日期：2026-10-24（Asia/Taipei）。本文是 APK 配套改造说明。本任务只修改服务器和开发者后台，不修改、构建、签名、安装或发布 APK。服务器接口在候选版本验证并部署后才可使用；不能把本文视为已经上线。

## 目标与边界

开发者后台“通知 → 推送事件”的十个全站开关统一控制 iPhone、Google Web Push 和 Android 直连的事件许可。Android 接收端读取服务器决定，不保存第二套事件开关或另行猜测通知类型。

保留目前的 User API Key 授权、长连接 MessageBus、`NotificationSync` 分页补收、请求预算、退避重试、后台服务、通知权限、渠道、包名及签名。保留现有通知点击目标和锁屏隐私设置。Google 版仍使用浏览器 Web Push，不启动直连服务。

这些开关只控制设备通知。站内记录、未读状态、计数、邮件、提醒时间和原有收件人产生方式继续由原流程处理。切换或保存开关不向任何用户发送“设置已变更”通知，也不补发历史事件。

旧 APK 不读取新字段，因此在 APK 配套更新并安装前，不能承诺其通知文案或事件筛选已经统一。

## 接口

在原有请求上添加一个查询参数：

```http
GET /notifications.json?silent=true&limit=60&offset=0&device_push=true
Accept: application/json
User-Api-Key: <现有授权，不新增权限>
User-Api-Client-Id: <现有 client id>
```

`offset` 继续采用现有的 0、60、120……。不新增轮询接口或请求频率。现有认证和通知可见性检查继续适用。

服务器在每条可见通知上附加字段：

```json
{
  "id": 123,
  "notification_type": 2,
  "read": false,
  "topic_id": 456,
  "post_number": 3,
  "isbf_device_push": {
    "version": 1,
    "enabled": true,
    "title": "关于选课的讨论",
    "body": "你收到一条新回复。"
  }
}
```

| 字段 | 类型 | 处理方法 |
| --- | --- | --- |
| `version` | integer | 本版本为 `1`；只处理明确支持的版本。 |
| `enabled` | boolean | `false` 时跳过系统通知，仍参与游标推进；只有严格的 `true` 才允许发送。 |
| `title` | string | 已生成的纯文本标题，直接显示；不追加用户名、站点名或操作。 |
| `body` | string | 已生成的操作提示，直接显示；不读取或拼接正文、摘要、私信、聊天内容。 |

普通 `/notifications.json`（不带 `device_push=true`）不增加该字段。通知列表中的行、`id`、`read`、未读计数和分页合同不因开关开闭而改变。`enabled` 由服务器当前开关、事件类别和用户已加入的日程计算。

### 点击目标楼层（2026-10-27 修复）

带 `device_push=true` 时，帖子事件的顶层 `post_number` 指向触发这条通知的新回复；合并未读回复保留的较早楼层不再作为设备通知的跳转目标。已接入此接口的 APK 继续由 `NotificationProtocol.target` 使用顶层 `topic_id` 和 `post_number`，无需因本次修复更新 APK。元数据版本及字段保持不变；尚未接入该接口的旧 APK 仍按本文原有要求改造。

普通通知列表继续保留站内的首个未读位置及合并规则，数据库记录、未读状态、计数和分页不变。触发帖子已不存在、不可见或不属于该话题时，保留原有目标。

设备上已有的系统通知仍保留发出时的目标。上线后应使用新产生的通知验证，旧通知不会自动重发。

## 接收端改动位置

基于现有实现，改动集中于三个位置；这只是文件定位说明，需在实际 APK 任务开始时重新核对最新源码。

1. `ForumNotificationService.sync`：在原有通知列表 GET 上加 `device_push=true`。
2. `NotificationProtocol.fresh` 或 `NotificationSync` 的发送循环：读取 `isbf_device_push.enabled`，过滤发送对象。`highWater` 和分页终止判断必须继续使用全部返回行。
3. `NativeNotifications.post`：使用服务器 `title`、`body` 替代当前“来自某用户的论坛新动态”。保留权限、点击跳转、归属、tag/id、渠道和锁屏公开版本的行为。

逻辑示意（不替代实际工程实现）：

```text
按现有 offset 拉取最多五页
用全部返回行计算 highWater 和分页终止条件
若为首次同步：只保存 highWater，不发送历史通知
否则：
  选取 id > 原游标且 read == false 的行，保持原有顺序
  发送前先校验本批所有新通知的元数据版本及字段类型
  任一元数据不兼容：本批不发送，保留原游标并按现有策略重试
  全部校验通过后逐行处理：
    enabled == false：跳过发送
    enabled == true：使用 title/body 调用现有系统通知函数
全部处理成功后，按原有规则保存 highWater
```

必须把“被服务器关闭的事件”和“发送失败”区分开：前者成功跳过并继续推进游标，不能走“通知权限不可用”的异常重试路径。权限不足或真正发送失败仍沿用原来的失败策略。

若待发送的新通知缺少元数据、版本不支持或字段类型错误，不回退为“允许所有事件”，也不从正文组装内容。保留原游标，按现有重试策略等待兼容响应，并在现有诊断页说明“通知服务暂不支持此版本”。首次建立游标仍按现有规则只记录历史边界。空列表无需元数据。

元数据校验放在发送整批通知之前，避免发现不兼容响应时，已有部分通知发出、重试后再次弹出。

开关由关改开不会触发即时通知；已在关闭期间跳过并越过游标的事件不再回补。保留正常离线期间尚未同步的新通知补收行为。

## 十个统一事件

编号沿用本任务最初的通知清单，不是 Discourse `notification_type` 的数值。

| 原编号 | 后台开关 | 初始值 | 包含事件 |
| --- | --- | --- | --- |
| 01 | 收到点赞 | 关 | 点赞和合并点赞 |
| 02、03 | 收到回复 | 开 | 回复、表情回应，共用一个开关 |
| 04、05 | 收到 @ | 开 | 个人提及、用户组提及 |
| 08、09、10 | 关注有新消息 | 开 | 关注主题、板块和标签的原有新主题/回复提醒 |
| 14 | 收到私信 | 开 | 私信和私信中的新回复 |
| 18 | 聊天有新消息 | 开 | 原有聊天消息与已关注聊天串提醒 |
| 19 | 聊天收到 @ | 开 | 聊天提及 |
| 24 | 主题定时提醒 | 关 | 用户设置的主题定时提醒 |
| 26 | 已加入日程的活动提醒 | 开 | 仅限已加入个人日程且当前可见的活动；沿用原提醒时间 |
| 27 | 日程变更 | 关 | 用户已加入的日程发生变更或取消 |

初始值用于服务器配置默认值，不应显示为正式后台的审查说明，也不能在 APK 内写成永久白名单。其他事件是否允许由服务器按现有 iPhone 规则决定。

该接口只给现有通知记录提供许可和文案，不创建聊天通知记录、不改变 MessageBus 事件、也不新增活动计时器。现有直连机制没有取回的事件，不能因本文而宣称已经实现接收。

## 文案

标题：帖子用对应帖子标题；私信用私信主题；聊天用频道名或私聊名称；活动用对应活动帖子标题。没有可用标题时由服务器提供站点名作为回退值。

| 事件 | 内容 |
| --- | --- |
| 点赞 | 你的帖子收到点赞。 |
| 回复 | 你收到一条新回复。 |
| 表情回应 | 你的帖子收到表情回应。 |
| 个人提及 | 有人在帖子中 @ 了你。 |
| 用户组提及 | 有人在帖子中 @ 了你所在的用户组。 |
| 关注更新 | 你关注的内容有新消息。 |
| 私信 | 你收到一条新私信。 |
| 聊天消息 | 你收到一条新的聊天消息。 |
| 聊天提及 | 有人在聊天中 @ 了你。 |
| 主题提醒 | 你设置的主题提醒已到时间。 |
| 活动即将开始 | 你加入日程的活动即将开始。 |
| 活动进行中 | 你加入日程的活动正在进行。 |
| 活动结束 | 你加入日程的活动已结束。 |
| 日程更新 | 你添加的日程有更新，请查看。 |
| 日程取消 | 你添加的日程已取消。 |

这些字符串在服务器本地化；APK 不复制第二套中文/英文模板。

## 配套验收

- 关闭/开启每类事件：三个渠道的设备许可一致，站内通知仍存在，邮件规则保持。
- 保存设置：仅后台成功提示，不出现站内通知、系统通知、邮件或历史回补。
- 回复和表情回应、个人/组提及共用开关，文案仍准确区分。
- 未加入个人日程的活动不弹出；加入后按原定时间提醒；移除后停止后续提醒。
- 不带参数的通知 API 行、未读状态和分页与原来一致。
- 连续多页被关闭事件仍推进游标，不重复抓取或后来补发；混合允许/关闭事件不漏掉允许行。
- 首次同步不发送历史；断网补收、权限失败、重试和限流继续按现有流程。
- 标题很长、包含 HTML 特殊字符或 emoji 时显示为安全纯文本；正文、摘要、私信和聊天内容均不出现。
- 元数据缺失、非法类型、不支持版本时不绕过服务器设置；诊断明确，兼容响应恢复后继续。
- Google 版继续走原 Web Push；直连版不新增订阅、后台通道或权限。

服务端部署、APK 改造、APK 安装和真机送达是不同阶段，应分别记录实际结果。本文不声称已完成 APK 配套或真机验收。
